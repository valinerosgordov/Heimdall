## 2. Verified findings (severity = post-verification, calibrated for a single-operator self-hosted pet tool)

### CRITICAL
- **A1 — JWT signing-secret insecure fallback.** `Api/Program.cs` — `?? "heimdall-dev-insecure-…"`. Validator accepts a source-committed key if `Heimdall:Jwt:Secret` is unset → forgeable operator tokens in prod. (Login *refuses* without a secret, but validation doesn't — asymmetric.) **REAL. → FIX (fail-fast).**

### HIGH
- **A2 — Alert "sustained for duration" is illusory.** `AlertEvaluationService` — `breached = points.Count>0 && All(IsBreached)` checks "all present samples breach", not "breach covered the window". A single/sparse sample fires immediately; the `DurationSeconds` knob is misleading. **REAL (known simplification). → FIX (require window coverage).**
- **A3 — Telegram bot token leaks into telemetry.** `TelegramAlertChannel` builds `…/bot{Token}/sendMessage`; `AddHttpClientInstrumentation` records `http.url` → token in console/OTLP traces. **REAL (only if Telegram configured). → FIX (filter from OTel).**
- **A4 — Agent push has no per-request timeout.** Typed `HttpClient` uses default 100s; on a 5s loop a hung server stalls collection ~20 cycles, silently dropping samples. **REAL. → FIX (timeout).**
- **A5 — SSE reconnect causes duplicate load.** `useOverview` starts a 3s poller on `onerror` but never stops it when SSE recovers (`onmessage`), and EventSource auto-reconnects → both run. **REAL. → FIX (stop poller on recovery).**

### MEDIUM
- **A6 — Malformed ingest body 500s.** `IngestMetricsHandler` derefs `request.Samples` with no null guard; `{"hostName":"x","samples":null}` → NRE → 500 (not 400). **REAL. → FIX (guard).**
- **A7 — `last_seen_at` touched before/independent of insert → false ONLINE.** Touch runs on any authenticated push even if 0 samples accepted or the COPY later fails. Low live impact (our agent always sends valid samples) but a real false-success path. **REAL. → FIX (touch only on accepted>0).**
- **A8 — Agent key file is plaintext, world-readable on Linux (0644), non-atomic.** `AgentKeyStore`. **REAL. → FIX (0600 + atomic write).**
- **A9 — Login credential check short-circuits → username-timing oracle.** `JwtTokenService` `usernameEquals && KeyHasher.Verify`. Low value (1 user). **REAL. → FIX (no short-circuit).**
- **A10 — HTTP health probe follows redirects.** `healthchecks` client leaves `AllowAutoRedirect=true`; a target 302→elsewhere is marked "up" for the wrong endpoint. **REAL. → FIX (disable redirects).**

### MEDIUM — documented & deferred (rationale)
- **A11 — HtmlEncode(name) at storage vs raw-name lookup mismatch.** Breaks enroll/ingest for host names with `& < > " '`. **Verified real but unreachable**: Windows/Linux hostnames cannot contain HTML-special chars. Also touches the stated "HtmlEncode input" convention. **DEFER** — needs a product decision (store-raw + encode-at-render vs normalize-on-lookup). No live impact.
- **A12 — Agent drops samples on push failure (no buffer/retry).** Real resilience gap; bounded buffer/`Channel<T>` + `AddStandardResilienceHandler` recommended. **DEFER** (moderate effort; gaps during outages acceptable for v1; A4 reduces the worst case).
- **A13 — No runtime validation of API responses (`.json() as T`).** Convention prefers Zod. **DEFER** (same-author backend; low real risk).
- **A14 — Enroll silently rotates an existing host's key.** Re-enroll overwrites `agent_key_hash`, killing the live agent silently. **DEFER** — recommend a rotate flag + audit log.

### LOW / by-design (not fixing)
- **SSRF "fix" rejected by design:** blocking loopback/private IPs would break the product's whole purpose — Heimdall *monitors your own internal hosts* (`timescale-tcp localhost:5432` is a legitimate target). Mitigation applied: disable auto-redirect (A10). Targets are created only by the authenticated single operator (trusted).
- **Offline host shows last-known values** (`GetLatestPerHostAsync` unbounded): by design — the OFFLINE badge conveys staleness; last-known values are useful (Grafana-style). 
- **localStorage token / 8h lifetime / no refresh rotation:** known simplification, already documented in README.
- **`ConfigureAwait(false)` absent in Infrastructure:** no runtime impact under ASP.NET Core (no SyncContext). Team/style call.
- **SSE: 3 DB connections/tick, no server lifetime cap or rate-limit:** fine at single-operator scale; batch + cap recommended if multi-user.
- **Touch+insert not in one transaction (A7 sibling):** rare; acceptable.
- Redundant enum double-validation; silent `_ =>` enum fallthroughs; `ToString().ToLowerInvariant()` allocs; DB-init catch-all retry; `agent_key_hash` via ALTER — all cosmetic.

## 3. Cross-cutting themes
1. **Secret hygiene under telemetry** (A1, A3, SSE token-in-query): OpenTelemetry URL capture + config fallbacks widen secret exposure. Fix fallbacks; filter sensitive clients from tracing.
2. **Silent success** (A7, A12, alerting deliver-and-forget): monitoring that can look healthy while storing/sending nothing. Tighten the touch/insert and alert-coverage paths.
3. **Heuristic correctness** (A2): the alert duration semantics need real window coverage.

## 7. Remediation status (2026-06-07)

**Fixed & verified (10):**
- **A1** — JWT secret now fails fast (`?? throw`) instead of an insecure committed fallback. *(Live: login still 200; protected endpoints 401 without token.)*
- **A2** — Alert evaluator now requires sustained coverage (`IsSustainedBreach`: all samples breach AND span ≥ ½ duration), so a single transient sample no longer fires. *(Live: sustained rule fired on real data; build+tests green.)*

- **A7** — `last_seen_at` is touched only after a successful insert with ≥1 accepted sample (no false ONLINE). *(Live: host online with real cpu/disk.)*
- **A8** — Agent key file written atomically (temp→move) with owner-only perms (0600) on Linux.
- **A9** — Login credential check no longer short-circuits (username timing oracle removed).
- **A10** — Health-check HTTP client disables auto-redirect (a 302 can't mark the wrong endpoint "up").
